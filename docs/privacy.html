Your data & the project

Privacy notice

FinVault is a personal, self-hosted finance tracker maintained by Anand George. This notice describes the application and the maintainer’s personal installation. Other operators are responsible for the data practices of their own installations.

Gmail access

FinVault uses Google OAuth to request the https://www.googleapis.com/auth/gmail.readonly scope. This permission allows reading Gmail messages and metadata; it does not permit sending, modifying, or deleting email. See Google’s description of Gmail scopes.

The permission covers reading your mailbox. The current ingestion process selects messages using configured Gmail labels associated with transactions. Label selection determines which messages are retrieved; the OAuth permission itself is broader than those labels.

The application communicates with Google’s authentication services and Gmail API to authorize access, refresh access tokens, and retrieve email. Google’s handling of that communication is described in Google’s privacy policy.

What is stored and why

FinVault stores data in a local SQLite database on the computer or server running the application. It uses those records to parse transaction emails and provide financial history and dashboard summaries.

  • Email records: Gmail message identifiers, sender, subject, received date, ingestion label, and email body content in text and/or HTML form.
  • Transaction records: parsed amounts, currencies, debit or credit type, merchants, dates, account identifiers found in the emails, sources, references, and links to the associated email records.
  • OAuth credentials: the application saves authorization tokens, including a refresh token when supplied, in a local token file for subsequent Gmail access.
  • Operational logs: ingestion and parsing logs can include message identifiers and subjects, as well as processing counts and errors.

Messages placed in an ingestion label may contain information beyond transaction details. That content can be retained in the email records even when a transaction cannot be parsed.

Hosting, access, and sharing

In the maintainer’s personal installation, email and transaction records stay in a local SQLite database. OAuth tokens and operational logs are also stored locally. These records are not uploaded to another server. The installation has no remote access, remote monitoring, or external analytics.

The application’s internet connections are limited to retrieving email through the Gmail API and Google authentication, including token refresh. The public informational website is hosted separately and has no connection to the local financial records.

The self-hosted application serves stored transaction data through its API and dashboard. Access to another operator’s installation depends on that operator’s host and network settings. Local storage by itself does not establish encryption or access controls; this notice makes no such guarantees.

Retention and withdrawing access

The current application does not automatically expire or delete email records, transactions, OAuth token files, or logs. They remain on the host until manually removed or replaced by the operator. No fixed retention period is promised.

For questions about retention or deletion in the maintainer’s installation, email anandvgeorge@gmail.com. Operators of other installations manage their own local records and any backup copies.

You can remove FinVault’s Google account authorization through Google’s third-party connections settings. Revoking access stops future authorized Gmail retrieval; it does not remove records already stored by an installation. Stop ingestion before removing local tokens or data, and handle backup copies separately.

Backups

FinVault does not automatically create backups. Any local backup copies, including those made during manual database maintenance, are managed by the operator.

Users of self-hosted installations may create backups at their discretion. They are responsible for choosing where those copies are stored, who can access them, how long they are retained, and how they are deleted.

This public website

These informational pages contain no Gmail sign-in flow, transaction dashboard, analytics scripts, or external fonts. When hosted on GitHub Pages, GitHub logs visitors’ IP addresses for security purposes. Read GitHub’s Pages data collection notice and GitHub’s privacy statement for details.
